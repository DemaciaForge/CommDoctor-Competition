# AI 辅助开发工作流程

## 概述

本文档定义 CommDoctor 项目的 AI 辅助开发工作流程，确保所有 AI 协作过程真实、可追溯、符合竞赛要求和学术规范。

## AI 工具信息

**主要 AI 工具：** Claude (Anthropic)  
**模型版本：** Opus 5.5  
**使用方式：** Claude Code (桌面应用)  
**开发环境：** Windows 11, Python 3.12.10, Git 2.55.0

## 标准开发循环

每个开发任务遵循以下流程：

```
┌─────────────────┐
│  用户需求       │ ← 用户用自然语言描述任务
└────────┬────────┘
         ↓
┌─────────────────┐
│ Prompt 归档     │ ← 保存原始 Prompt（不得改写）
└────────┬────────┘
         ↓
┌─────────────────┐
│  方案设计       │ ← Claude 提出技术方案
└────────┬────────┘
         ↓
┌─────────────────┐
│  AI 编程        │ ← Claude 生成代码
└────────┬────────┘
         ↓
┌─────────────────┐
│  自动化测试     │ ← pytest 验证功能
└────────┬────────┘
         ↓
┌─────────────────┐
│  用户验收       │ ← 用户确认结果
└────────┬────────┘
         ↓
┌─────────────────┐
│  Git 提交       │ ← 记录到版本控制
└────────┬────────┘
         ↓
┌─────────────────┐
│ 开发日志更新    │ ← 更新项目文档
└─────────────────┘
```

## Prompt 归档制度

### 归档位置
所有开发相关的 Prompt 归档在：
```
docs/prompt-logs/
├── stage-00/           # 阶段 00 的 Prompt
├── stage-01/           # 阶段 01 的 Prompt
├── stage-02/           # ...
└── ...
```

### 归档格式

每个任务创建一个 Markdown 文件，命名格式：
```
YYYY-MM-DD_taskID_brief-description.md
```

示例：`2026-10-13_00-A_environment-check.md`

**文件结构：**

```markdown
# 任务记录：[任务简述]

## 任务元数据

- **任务编号：** [例如 00-A]
- **日期：** YYYY-MM-DD
- **时间：** HH:MM (24小时制)
- **阶段：** 阶段 XX
- **AI 模型：** Claude Opus 5.5
- **执行工具：** Claude Code (Desktop)

## 用户原始 Prompt

[完整粘贴用户的原始输入，不得修改或总结]

## Claude 方案设计

[记录 Claude 提出的技术方案要点]

## 执行过程

### 文件变更
- 创建：[文件列表]
- 修改：[文件列表]
- 删除：[文件列表]

### 命令执行
[记录执行的关键命令和输出]

### 测试结果
[粘贴测试命令和完整输出]

## 用户验收

- **结果：** [通过 / 需要修改 / 失败]
- **用户反馈：** [记录用户的评价和意见]

## Git 提交信息

- **提交哈希：** [commit hash]
- **提交信息：** [commit message]
- **提交时间：** [timestamp]

## 备注

[任何额外的说明、问题或改进建议]
```

### 归档时机

- **立即归档：** 每个重要开发任务完成后
- **批量归档：** 如果是连续的小修改，可以在一个 Git 提交前归档
- **禁止补录：** 不允许事后补写"历史" Prompt

### 隐私保护

**可以进入公共仓库的内容：**
- 技术讨论
- 代码问题
- 测试结果
- 方案设计

**必须过滤的敏感信息：**
- API 密钥
- 个人身份信息（真实姓名、学号、联系方式）
- 竞赛账号密码
- 完整的私人对话（如包含个人隐私的讨论）

**建议做法：**
1. 创建两份归档：
   - `docs/prompt-logs/` - 公开版本（过滤敏感信息）
   - 本地备份 - 完整版本（不上传 Git）

2. 在 .gitignore 中排除私密目录：
   ```
   docs/private/
   ```

## Git 提交规范

### 提交粒度
- **一次提交 = 一个完整的功能单元**
- 避免"保存进度"式的碎片化提交
- 避免为了增加提交数量而人为拆分

### 提交信息格式

```
<类型>: <简短描述>

<详细说明>（可选）

<关联信息>
- Task: [任务编号]
- Files: [主要修改的文件]
- Tests: [相关测试]

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

**类型标签：**
- `feat:` 新功能
- `fix:` Bug 修复
- `docs:` 文档更新
- `test:` 测试相关
- `refactor:` 代码重构
- `chore:` 构建/工具/配置

**示例：**

```
feat: 实现 BPSK 调制器和解调器

实现基于 NumPy 的 BPSK 调制和解调功能，包括：
- 二进制数据到符号映射
- 载波调制
- 相干解调
- 符号判决

- Task: 01-B
- Files: src/core/modulation.py
- Tests: tests/test_modulation.py (15 passed)

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

### 提交时机
- 功能实现并通过测试后
- 文档完成后
- Bug 修复并验证后
- **不在中途、未完成或未测试时提交**

### 禁止的提交行为
- ❌ 修改历史提交（除非是私有分支的最近提交）
- ❌ 伪造提交时间
- ❌ 无意义的空提交
- ❌ 仅为增加提交数量的格式化修改

## AI 对话完整备份

### Claude Code 对话导出

Claude Code 桌面应用可能提供对话导出功能。如果支持：
1. 定期导出完整对话历史
2. 保存为 JSON 或其他结构化格式
3. 存储在本地私密目录（不上传 Git）

### 手动截图备份（备选）

如果无法自动导出：
1. 对关键对话进行截图
2. 保存到本地私密文件夹
3. 在 Prompt 归档中注明"完整对话已截图保存"

### 注意事项
- ⚠️ 完整对话可能包含个人隐私信息，**不要**直接上传公共仓库
- ✅ 公开的 Prompt 归档只需包含技术相关内容
- ✅ 完整对话作为个人证据保留，必要时可向竞赛组织方提供

## 常见问题

### Q: 是否需要记录所有与 Claude 的对话？
**A:** 记录所有与开发直接相关的对话。日常咨询、概念学习等可以选择性记录。

### Q: 如果一次对话涉及多个任务怎么办？
**A:** 可以创建一个总的记录文件，或者按主要任务归档，在其中列出所有涉及的子任务。

### Q: Prompt 归档是否可以总结而不是完整粘贴？
**A:** 不可以。必须保留用户原始 Prompt 的完整文本，这是证明 AI 协作真实性的关键。

### Q: 如果忘记及时归档怎么办？
**A:** 尽快补充归档，并在记录中诚实说明"补充记录于 [日期]"。但要避免频繁事后补录。

### Q: Git 提交中的 Co-Authored-By 是否必须？
**A:** 是。这是明确标识 AI 参与的重要方式，也是竞赛要求的一部分。
